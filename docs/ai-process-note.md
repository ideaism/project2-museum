# AI Process Note

Codex was used as a coding and documentation assistant for The Glitching Archive. Its role was to help scaffold React components, route structure, TypeScript contracts, fallback states, QA documentation, deployment notes, and draft interface copy.

Codex was not used as an authority for verified museum facts. Historical claims, maker names, dates, collection IDs, political affiliations, ownership histories, protest details, and donor contexts remain placeholders unless supplied by collection records, object photographs, labels, catalogues, or other verified sources.

The prototype uses AI-supported interpretation only when it is labelled as inference, speculation, visitor contribution, or redaction. This is an ethical requirement of the project: the interface must show uncertainty rather than smoothing it into a false institutional voice.

## Authorship

The project concept, archive ethics, route requirements, and layer model come from the user-supplied project brief. Codex supported implementation and documentation, but curatorial responsibility remains with the project author and any future museum collaborators.

## Source Rule

AI must not invent museum metadata. If evidence is missing, the record should say that evidence is missing.

## Right to Opacity

The archive does not force every absence into a story. Redaction, withheld identity, contested memory, and unresolved evidence are treated as legitimate archive states. This protects people and communities whose histories may be harmed by overconfident reconstruction.

## Local Visitor Contributions

Visitor annotations in the MVP are local-only. They are useful for demonstrating co-curation, but they are not verified facts and are not shared across devices.
